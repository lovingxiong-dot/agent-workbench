## Commit 1：Metadata Contract & Base Model（v6.11.0-alpha.2）✅ 已冻结

目标：冻结 `agent_workbench/metadata/` 目录与 `MetadataDefinition` 契约，让 Runtime、Workbench、Plugin、CLI、Web 共享同一套对象描述语言。

### 文件规划（目录一次性冻结）

```text
agent_workbench/metadata/
    __init__.py
    types.py       # 公共类型别名与枚举（ValueType, MetadataType 等）
    errors.py      # Metadata 相关异常
    model.py       # MetadataDefinition / MetadataProperty / MetadataAction / MetadataStatistics
    registry.py    # MetadataRegistry：register / get / all
    adapter.py     # MetadataAdapter：空实现或基础实现，为 v6.12.x Plugin Metadata 预留
```

### 核心对象

#### `MetadataDefinition`
静态描述一个 Runtime 对象。

- `id: str`
- `type: str`（`provider`, `mcp`, `skill`, `workflow`, `prompt`, `memory` 等）
- `name: str`
- `description: str`
- `icon: str`（平台无关标识，如 `"provider"`, `"mcp"`, `"skill"`）
- `properties: list[MetadataProperty]`
- `statistics: list[MetadataStatistics]`
- `actions: list[MetadataAction]`
- `tags: list[str]`
- `enabled: bool`

#### `MetadataProperty`
描述对象的可配置属性。例如 `temperature`, `api_key`, `endpoint`, `enabled`。

- `id: str`
- `name: str`
- `description: str`
- `value_type: ValueType`（string / int / float / bool / list / dict / secret / path / enum）
- `current_value: Any`
- `default_value: Any`
- `options: list[Any]`（可选值列表，用于 enum / select）
- `editable: bool`
- `sensitive: bool`（标记 secret / api_key，但不指定具体 UI 控件）
- `category: str`

#### `MetadataAction`
描述对象可触发的操作。例如 `Connect`, `Disconnect`, `Refresh`, `Install`, `Remove`。

- `id: str`
- `label: str`
- `description: str`
- `icon: str`
- `enabled: bool`

#### `MetadataStatistics`
描述对象的运行时统计。例如 `tokens`, `latency`, `memory_usage`, `version`。

- `id: str`
- `name: str`
- `value: Any`
- `unit: str`
- `timestamp: datetime | None`

## Commit 2：OpenAI Provider — First Real LLM Link（v6.11.0-beta.1）

目标：打通第一条真实链路，让 Workbench 从架构进入产品阶段。

```text
User
   ↓
Workbench UI
   ↓
Manager AI
   ↓
Capability
   ↓
OpenAI Provider
   ↓
LLM
   ↓
Response
   ↓
UI
```

### 文件规划
- `agent_workbench/services/openai_provider.py` — 真实 OpenAI Provider 实现
- `agent_workbench/services/model_provider.py` — Provider 基类/协议
- `agent_workbench/runtime/modules/model_module.py` — 接入 Provider 选择，支持切换 active provider
- `agent_workbench/runtime/decision/manager_ai.py` — 普通聊天路由到 `chat` Capability
- `tests/integration/test_openai_chat_loop.py` — 非 GUI 集成测试

### 任务
- [x] 让 `ManagerAI` 将普通聊天请求从 `CHAT` 改为 `ACTION`，目标 Capability 为 `chat`。
- [x] 让 `CapabilityResolver` 对 `general_query` 生成 `chat` CapabilityChain（`engine_capability=text_generation`）。
- [x] `OpenAIProvider` 从 ConfigStore 读取 `api_key`、`base_url`（可选）、`model`，使用 `openai` 库调用 `chat.completions.create`。
- [x] `OpenAIProvider.chat()` 返回非流式字符串响应，`chat_stream()` 返回流式 token 生成器。
- [x] `ModelModule` 根据 `model.providers` 配置注册 OpenAI Provider，支持切换 active provider。
- [x] 实现一条最小对话链路：
  - 用户输入 → `RuntimeRequest` → Decision Layer → Capability → Provider → LLM → 返回文本
- [x] 非 GUI 集成测试覆盖：
  - 使用 mock HTTP 验证请求/响应格式
  - 验证 `api_key` 不随响应返回
  - 验证错误状态传播

### 验收标准
- [ ] 配置一个 OpenAI Provider 后，Runtime 能返回真实或 mock 的 LLM 响应。
- [ ] `pytest` 全量通过。
- [ ] 不引入 MCP、Workflow、Tool Calling、多模型、Memory 等依赖。

## 现在不做清单

- **Schema-driven UI**：不自动生成控件，v6.12.x 再做。
- **Runtime Executors**：ProviderRuntime / ToolRuntime / SkillRuntime 放到 Schema Foundation 之后。
- **新增 Runtime 类型**：Knowledge / Persona / Browser / Plugin / Gateway / Digital Identity 不接。
- **多 Provider 接入**：Claude / Gemini / Kimi / Qwen / DeepSeek（OpenAI 跑通后再接）。
- **复杂 Workflow DAG**：只做基础串行任务流 A → B → C，且放到更晚阶段。
