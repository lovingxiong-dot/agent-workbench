# v6.11.x 可执行任务清单：Metadata-driven Workbench

> **目标**：让所有已支持对象具备统一的 Metadata 描述能力。
>
> **每阶段原则**：Workbench 今天比昨天多支持一种什么类型的对象，而无需修改代码？
>
> **核心规则**：UI 永远只认识 `PresentationModel`，不直接调用 Service；`BaseRuntimeModule.metadata()` 返回平台无关的 Capability Metadata。
>
> **阶段边界**：
> - v6.11.x：Metadata-driven（统一描述对象）
> - v6.12.x：Schema-driven（统一描述配置，自动生成 UI）
> - v6.13.x：Plugin-driven（零代码扩展）

---

## Commit 1：Metadata Contract & Base Model（v6.11.0-alpha）

目标：定义 `ModuleMetadata` 数据结构，统一 Runtime Module 的 `metadata()` 返回契约。

### 文件规划
- `agent_workbench/metadata/__init__.py`
- `agent_workbench/metadata/model.py` — `ModuleMetadata`, `PropertyMetadata`, `StatisticMetadata`, `ActionMetadata`
- `agent_workbench/metadata/factory.py` — 从 dict / dataclass 构造 Metadata 的工厂
- `agent_workbench/metadata/adapter.py` — `ModuleMetadata → ModulePresentation` 的跨层适配器
- `agent_workbench/metadata/schema.py` — Schema 数据模型（v6.12.x 启用）
- `agent_workbench/metadata/registry.py` — Metadata Registry（v6.12.x 启用）
- `agent_workbench/ui/presentation/model.py` — `ModulePresentation` 等 UI 消费模型
- `agent_workbench/runtime/modules/base.py` — 修改 `BaseRuntimeModule.metadata()` 返回类型为 `ModuleMetadata`

### 任务
- [ ] 定义 `ModuleMetadata`：
  - `id: str`
  - `type: str`
  - `name: str`
  - `description: str`
  - `icon: str`（平台无关标识，如 `"provider"`, `"mcp"`, `"skill"`）
  - `properties: list[PropertyMetadata]`

- [ ] 定义 `PropertyMetadata`：

  - `editable: bool`
  - `category: str`（分组标签）
- [ ] 定义 `StatisticMetadata`：
  - `id`, `name`, `value`, `unit`, `timestamp`
- [ ] 定义 `ActionMetadata`：
  - `id`, `label`, `description`, `icon`, `enabled`
- [ ] 更新 `BaseRuntimeModule.metadata()` 契约，返回 `ModuleMetadata`。
- [ ] 提供 Metadata 校验器，确保所有字段类型正确、无 UI 概念混入。
- [ ] 非 GUI 单元测试覆盖 Metadata 模型、工厂、校验器。

### 验收标准

## 现在不做清单

- **Schema-driven UI**：不自动生成控件，v6.12.x 再做。
- **Runtime Executors**：ProviderRuntime / ToolRuntime / SkillRuntime 放到 Schema Foundation 之后。
- **新增 Runtime 类型**：Knowledge / Persona / Browser / Plugin / Gateway / Digital Identity 不接。
- **真实 Provider 接入**：Claude / Gemini / OpenAI / Kimi / Qwen / DeepSeek 不接。
- **复杂 Workflow DAG**：只做基础串行任务流 A → B → C，且放到更晚阶段。
