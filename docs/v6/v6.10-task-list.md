# v6.10.x 可执行任务清单

> **原则**：Agent Workbench 是 V6 Runtime 的官方产品化验证平台。任何任务完成的标准是：能在 Workbench 中安装、运行、验证。

## 第一阶段：GUI Platform（v6.10.0-alpha）

目标：把 Workbench 打磨成每天可用的 IDE 主界面。

### 1.1 主窗口与基础布局
- [ ] 运行 `python main.py` 能稳定启动主窗口
- [ ] 窗口标题、图标、最小尺寸正确
- [ ] 三栏布局（左 / 中 / 右）正常显示
- [ ] 窗口几何状态持久化到 `ConfigManager`
- [ ] 主题切换（dark/light）生效并持久化

### 1.2 左侧会话面板
- [ ] 从 `SessionService` 加载会话分组列表（今天/昨天/最近7天/更早）
- [ ] 点击会话切换当前激活会话
- [ ] 新建会话按钮调用 `SessionService.create()`
- [ ] 删除会话按钮调用 `SessionService.delete()`
- [ ] 重命名会话调用 `SessionService.rename()`
- [ ] 置顶会话调用 `SessionService.pin()`
- [ ] 搜索会话调用 `SessionService.search()`

### 1.3 中间聊天区
- [ ] 从 `ChatService` 加载当前会话历史消息
- [ ] 用户输入消息追加到 UI 并调用 Runtime
- [ ] Assistant 回复以流式/块状方式显示
- [ ] 工具调用结果以可折叠卡片形式显示
- [ ] 清空当前会话历史

### 1.4 输入区
- [ ] 多行输入框支持 Shift+Enter 换行
- [ ] 发送按钮触发 `RuntimeRequest`
- [ ] 模式选择（ask/plan/craft 等）从 `ConfigManager` 读取并持久化
- [ ] 模型选择从 `ProviderRegistry` 读取

### 1.5 右侧工作区面板
- [ ] 终端面板可显示输出
- [ ] 文件浏览器显示当前项目路径
- [ ] 工具面板从 `ToolRegistry` 读取可用工具
- [ ] 面板切换状态持久化

---

## 第二阶段：Provider Framework（v6.10.x）

目标：打通 Provider Contract，先支持一个 Provider。

### 2.1 Provider Contract
- [ ] 定义 `ProviderDefinition`（id, name, type, config_schema, capabilities）
- [ ] 定义 `ProviderContext`（provider_id, model_id, params, credentials）
- [ ] 定义 `ProviderRegistry`（register / unregister / get / list）
- [ ] 将现有 `ModelProvider` ABC 接入 ProviderRegistry

### 2.2 Provider 配置
- [ ] `ConfigManager` 支持 `providers.{id}.type` 等配置
- [ ] Provider 配置在 UI 中可编辑
- [ ] Provider 配置变更后无需重启即可生效

### 2.3 第一个可运行 Provider
- [ ] EchoProvider 通过 ProviderRegistry 可被调用
- [ ] 或接入一个真实 LLM Provider（OpenAI / DeepSeek 等）
- [ ] Provider 调用结果进入 `RuntimeContext.result`

---

## 第三阶段：Tool Runtime（v6.10.x）

目标：Tool 可注册、可执行、可观测。

### 3.1 Tool Contract
- [ ] 确认 `ToolRegistry` 与 `Tool` dataclass 满足需求
- [ ] Tool 配置持久化到 `ConfigManager`
- [ ] Tool 启用/禁用/权限在 UI 中可配置

### 3.2 基础工具集
- [ ] `read_file(path)`
- [ ] `write_file(path, content)`
- [ ] `bash(command)` / `powershell(command)`
- [ ] `python(code)`

### 3.3 Tool 执行链路
- [ ] Tool 调用从 LLM 输出解析为 `ToolCall`
- [ ] `ToolCall` 通过 ToolRegistry 找到 handler
- [ ] 执行结果包装为 `ToolResult` 回到 `RuntimeContext`
- [ ] UI 中显示工具调用过程与结果

---

## 第四阶段：Skill Framework（v6.10.x）

目标：定义 Skill Contract，让能力可以「安装」。

### 4.1 Skill Contract
- [ ] 定义 `SkillDefinition`（id, name, version, capabilities, tools, provider_prefs）
- [ ] 定义 `SkillContext`（runtime_ctx, skill_params）
- [ ] 定义 `SkillRuntime`（load / unload / execute）
- [ ] 定义 `SkillRegistry`（register / unregister / list / get）

### 4.2 Skill 集成
- [ ] Skill 安装入口（目录扫描 / 手动注册）
- [ ] Skill 能力映射到 `CapabilityDefinition`
- [ ] Skill 工具映射到 `ToolRegistry`
- [ ] UI 中显示已安装 Skill 列表

### 4.3 先不做
- [ ] 不实现具体 Skill（Python Skill / Git Skill 等）
- [ ] 不做 Skill Marketplace
- [ ] 不做 Skill 版本升级/依赖管理

---

## 第五阶段：Workflow 基础（v6.10.x / v6.11.x 边界）

目标：基础串行任务流 A → B → C。

### 5.1 Workflow Contract
- [ ] 定义 `WorkflowDefinition`（steps, edges）
- [ ] 定义 `WorkflowStep`（id, capability, input_mapping, output_mapping）
- [ ] 定义 `WorkflowExecutor`（串行执行）

### 5.2 Workflow 集成
- [ ] Workflow 作为 Capability 接入 CapabilityRegistry
- [ ] UI 中可触发预定义 Workflow
- [ ] 执行状态显示在状态栏

### 5.3 先不做
- [ ] 复杂 DAG
- [ ] 条件分支
- [ ] 循环 / 并行

---

## 验收标准

每个阶段完成后必须满足：

1. **所有新增代码有非 GUI 单元测试**。
2. **Workbench 能稳定启动并演示该阶段功能**。
3. **`pytest` 全量通过**。
4. **`python -B scripts/audit_repository.py` 得分 ≥ 95**。
5. **相关文档更新**（必要时更新本清单、ROADMAP、数据层清单）。

---

## 当前不做清单

- Digital Identity / Agent Identity
- Identity Database
- 多 Provider 智能切换与路由
- 复杂 Workflow DAG
- MCP / Browser / External Service
- Plugin Marketplace
- Gateway / Distributed / Remote Runtime
