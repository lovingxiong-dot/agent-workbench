# v6.12 Task List — PresentationModel + Task 闭环

> **主线目标**：让 Workbench 从「有架构的框架」变成「可用的产品」。
>
> v6.11 完成了 Metadata Contract 与 Provider Registry；v6.12 的重点是：
> 1. 用 PresentationModel 彻底隔离 UI 与 Runtime。
> 2. 跑通第一条真实任务闭环（User → Manager → Planning → Capability → Provider → Streaming → Task → Trace → History）。
> 3. 通过真实使用验证架构稳定性，而不是继续增加抽象层。

---

## 全局约束

- **Metadata Contract 已冻结**（见 `PROJECT_BLUEPRINT.md`）：只允许 Additive Change，禁止 Breaking Change。
- **不再新增 Provider**：当前 7 个内置 Provider 已足够验证 Registry；未来 Provider 必须做到「零代码改动」接入。
- **UI 不拥有 Runtime / Provider / Resource**：UI 只通过 `PresentationModel` 读取，通过事件反向通信。

## Commit 10：ViewComponentRegistry 契约层（v6.12.0-beta.4）

### 文件规划
- `agent_workbench/ui/workbench/view_component.py` — `ViewComponentDefinition`。
- `agent_workbench/ui/workbench/view_component_registry.py` — `ViewComponentRegistry`。

- `tests/ui/test_view_component_registry.py` — 非 GUI 单元测试。

### 允许做（仅限三件）
- [x] 定义 `ViewComponentDefinition`：
  - `id: str`
  - `renderer: str`（renderer 标识，不实例化 Qt）
  - `supported_schema: list[str]`（可处理的 schema 类型）
  - `supported_binding: list[str]`（可消费的 binding namespace）
  - `default_size: dict | None`（如 `{"width": 400, "height": 300}`）
  - **不要更多字段**。

  - `register(definition: ViewComponentDefinition)`

  - **只有四个接口**。
- [x] `ViewSchemaRenderer` 改为 `render(component_id: str)` 入口：
  - 内部按 component_id 找到 `ViewComponentDefinition`。
  - 再委托到现有 `_render_toolbar` / `_render_status_bar` / `_render_inspector` / `_render_workspace`。
  - 这一步只做接口收敛，不新增任何组件实现。

- [x] ❌ Chart / Graph

### 架构意义
如果 12.1-12.4 与 rc.1 全部完成，v6.12 成为 V6 第一个「架构稳定版」：

```text
Package
    ↓
Metadata
    ↓
PresentationModel
    ↓
ViewSchema
    ↓
ViewComponentRegistry
    ↓
BindingContext
    ↓
Qt Renderer
    ↓
Runtime
```

后续所有扩展都是在这条主链上「装东西」，而不是推翻内核。

## 现在不做清单（v6.12 期间）

- **新增 Provider**：Registry 已足够，后续 Provider 必须零代码接入。
- **新增 Runtime 类型**：Knowledge / Persona / Browser / Plugin / Gateway / Digital Identity 不接。
- **Schema-driven UI**：v6.12 仍手动映射 PresentationModel，v6.13.x 再考虑从 Schema 自动生成控件。
- **Runtime Executors**：ProviderRuntime / ToolRuntime / SkillRuntime 放到 Schema Foundation 之后。
- **复杂 Workflow DAG**：只做基础串行任务流 A → B → C，且放到更晚阶段。
- **Multi-Agent / Marketplace / Remote / Web Plugin**：在 Task 闭环稳定前不做。
