## 2. Runtime Boundary 定义

### 2.1 Frozen Zone（冻结区 — 禁止修改）

以下区域已进入 Frozen 状态。任何修改必须经过 Architecture Review 并更新本报告。

| 层级 | 文件/目录 | 冻结原因 |
|------|-----------|---------|
| **Core Runtime** | `v6/runtime/orchestrator.py` | Task Lifecycle State Machine，所有 Agent 执行的基础 |
| **Core Runtime** | `v6/runtime/context.py` | RuntimeContext — 公共 ABI，所有 Engine/Module 的契约 |
| **Core Runtime** | `v6/runtime/event_bus.py` | EventBus — 异步事件循环，所有事件通信的基础 |
| **Core Runtime** | `v6/runtime/runtime.py` | AgentRuntime — 组合根，Orchestrator + EngineManager + EventBus |
| **Core Runtime** | `v6/runtime/enums.py` | RuntimeState 枚举，所有状态机的基础 |
| **Core Runtime** | `v6/runtime/types.py` | ChatMessage 等基础类型 |
| **Capability** | `agent_workbench/runtime/capability/model.py` | CapabilityDefinition — 纯数据契约 |
| **Capability** | `agent_workbench/runtime/capability/state.py` | CapabilityState 枚举 |
| **Capability** | `agent_workbench/runtime/capability/graph.py` | CapabilityRegistry — Tree 结构 |
| **Capability** | `agent_workbench/runtime/capability/chain.py` | CapabilityChain — 顺序契约 |
| **Interaction** | `agent_workbench/runtime/interaction/request.py` | RuntimeRequest — 统一外部输入契约 |
| **Interaction** | `agent_workbench/runtime/interaction/event.py` | InteractionEvent — UI 层事件协议 |
| **Interaction** | `agent_workbench/runtime/interaction/renderer.py` | UIEventRenderer — UI 渲染器协议 |
| **Interaction** | `agent_workbench/runtime/interaction/mapper.py` | RuntimeEventMapper — 事件映射 |
| **Config** | `agent_workbench/runtime/config_store.py` | ConfigStore — 统一配置存储（纯 Python） |
| **Config** | `agent_workbench/config/default.yaml` | 唯一配置源 |
| **Decision** | `agent_workbench/runtime/manager/decision_manager.py` | DecisionManager — 唯一决策入口 |
| **Package** | `agent_workbench/package/loader.py` | PackageLoader — manifest 扫描与验证 |
| **Package** | `agent_workbench/package/registry.py` | PackageRegistry — 包注册与生命周期 |

### 2.2 Boundary Rules（边界规则）

1. **RuntimeContext 禁止业务方法** — 不得添加 `ctx.call_llm()`、`ctx.search()` 等业务方法。RuntimeContext 是数据容器，不是服务对象。
2. **Interaction Layer 是唯一入口** — 所有外部请求（CLI/GUI/API）必须通过 `WorkbenchInteractionLayer` 进入 Runtime。禁止 UI 直接调用 `DecisionManager.decide()`。
3. **UI 只消费 InteractionEvent** — UI 不得直接订阅 `RuntimeEventBus`。流式事件通过 `UIEventRenderer` 协议获取。
4. **ConfigStore 不依赖任何 UI 框架** — ConfigStore 是纯 Python，Qt/Web/CLI 通过 Adapter 模式接入。
5. **DecisionManager 只调用一次** — 每个请求只经过一次决策，不重复。

## 8. 附录 A：Skill 与 Capability 的关系定义

### 8.1 问题

当前 `Capability` 和 `Skill` 两个概念容易在未来混淆。需要明确层级关系，避免 v6.15 出现概念冲突。

### 8.2 定义

| 概念 | 层级 | 定义 | 示例 |
|------|------|------|------|
| **Capability** | Runtime 原子能力 | 不可再分的执行单元，由 Engine 实现 | `tool.execute`、`memory.read`、`file.write`、`llm.chat` |
| **Skill** | Agent 组合能力 | 由多个 Capability 编排而成的上层能力，面向 Agent 使用 | `coding`、`research`、`assistant`、`quant-analysis` |

### 8.3 层级关系

```
Agent
  │
  │  声明拥有哪些 Skill
  │
  ▼
Skill
  │
  │  编排多个 Capability
  │
  ▼
Capability
  │
  │  绑定到 Engine
  │
  ▼
Engine / Tool
```

### 8.4 约束

1. **Capability 由 Runtime 定义** — 新增 Capability 需要注册到 `CapabilityRegistry`，绑定 Engine。
2. **Skill 由 Agent 声明** — 在 `manifest.yaml` 的 `skills` 字段中列出。
3. **Skill 不直接访问 Engine** — 必须通过 Capability 编排。
4. **Capability 不知道 Skill 的存在** — Capability 是底层原子，不感知上层组合。

### 8.5 示例

```yaml
# coding-agent 的 manifest.yaml
skills:
  - code-analysis:
      capabilities:
        - file.read
        - llm.chat
        - code.index
  - code-generation:
      capabilities:
        - file.write
        - llm.chat
        - tool.execute
```

## 9. 附录 B：Memory 架构边界预定义

### 9.1 问题

当前 `SessionModule` 只管理会话级别消息。未来必然出现多种 Memory 类型。如果 Memory 直接进入 Runtime Kernel，会破坏 Kernel 的纯粹性。

### 9.2 Memory 类型定义

| 类型 | 生命周期 | 存储 | 示例 |
|------|---------|------|------|
| **Session Memory** | 单次会话 | 内存 | 当前对话历史 |
| **Working Memory** | 单次任务 | 内存 | 任务中间结果、临时上下文 |
| **Long-term Memory** | 跨会话 | 持久化 | 用户偏好、历史决策、学习模式 |
| **Knowledge Memory** | 持久 | 向量库 | 项目文档、代码库、参考资料 |
| **Agent Memory** | Agent 级别 | 持久化 | Agent 专属知识、Skill 状态 |

### 9.3 架构约束

```
Agent
  │
  │  配置 memory 策略
  │
  ▼
MemoryProvider Protocol（类似 Provider 模式）
  │
  ├── SessionMemoryProvider
  ├── WorkingMemoryProvider
  ├── LongTermMemoryProvider
  ├── KnowledgeMemoryProvider
  └── AgentMemoryProvider
```

**关键原则：Memory 是 Provider，不是 Runtime Kernel 组件。**

1. Memory 不进入 Frozen Zone。
2. Memory 通过 `MemoryProvider` 协议接入，类似 `LLM Provider`。
3. `MemoryModule` 只做编排，不做存储。
4. 不同 Memory 类型可以有不同的后端（内存、文件、向量库）。

### 9.4 演进路线

| 阶段 | 版本 | 内容 |
|------|------|------|
| 当前 | v6.13 | `SessionModule` 管理会话消息（内存） |
| Step 1 | v6.15 | `MemoryProvider` 协议定义 |
| Step 2 | v6.15 | `SessionMemoryProvider` + `LongTermMemoryProvider` 实现 |
| Step 3 | v6.16 | `KnowledgeMemoryProvider`（向量库） |
| Step 4 | v7.0 | `AgentMemoryProvider`（Agent 专属记忆） |

## 10. 附录 C：Agent Identity Registry 战略定位

### 10.1 问题

`DecisionManager` 当前作为唯一决策入口是正确的，但未来如果所有 Agent 路由、Capability 选择、Policy 判断都堆积在 `DecisionManager` 中，它会膨胀为新的"上帝对象"。

### 10.2 未来拆分方向（v7.0 前关注）

```
DecisionManager（当前，冻结）

未来应拆分为：

├── Router              # 请求路由到哪个 Agent
├── PolicyEngine        # 权限与策略检查
├── CapabilityResolver  # 能力匹配与选择
└── PlannerSelector     # 规划器选择
```

**当前不需要修改，但 v7.0 前需要关注这个边界。**

### 10.3 Agent Identity Registry 定位

`AgentIdentityRegistry` 不是简单的"Agent 列表"，而是未来 Agent OS 的核心注册中心。

```
AgentIdentityRegistry
│
├── Identity        # Agent 身份（name, persona, version）
├── Model Binding   # 绑定的 LLM Provider + Model
├── Capabilities    # 拥有的 Capability 集合
├── Skills          # 声明的 Skill 列表
├── Permissions     # 运行时权限边界
├── Memory Policy   # 记忆策略配置
├── Lifecycle       # Agent 生命周期（install/update/uninstall）
└── Dependencies    # 依赖的其他 Agent
```

### 10.4 战略定位

```
Agent Identity Registry

类比：

┌─────────────────┬─────────────────────┬──────────────────────┐
│  App Store       │  Docker Registry     │  HR System           │
│  (分发)          │  (版本/依赖)         │  (身份/权限/生命周期)  │
└─────────────────┴─────────────────────┴──────────────────────┘
```

未来 `Agent Marketplace` 的基础就是 `AgentIdentityRegistry`。

### 10.5 与现有系统的关系

```
AgentIdentityRegistry（v6.14+）
  │
  │  注册 Agent Identity，管理生命周期
  │
  ├── PackageRegistry（已有）
  │     │
  │     │  Package 安装、扫描、加载
  │     │
  │     ▼
  │  Package = Agent 的物理载体
  │
  └── DecisionManager（已有）
        │
        │  根据 Agent Identity 路由请求
        │
        ▼
     Runtime
```

**关键：AgentIdentityRegistry 管理"谁"，PackageRegistry 管理"在哪"，DecisionManager 管理"做什么"。**

## 11. 禁止事项（v6.13+ 强制执行）

以下四条禁止事项从 v6.13-frozen 起永久生效，写入冻结边界。违反即视为架构污染。

### 禁止 1：Skill 不得进入 Runtime Kernel

**错误方向：**
```
Runtime
  └── SkillManager    ← 禁止
```

**正确方向：**
```
Agent Layer
  └── Skill Registry
```

**理由：** Skill 是 Agent 的组合能力，不是 Runtime 的基础设施。Runtime Kernel 不感知 Skill 的存在。

---

### 禁止 2：Memory 不得进入 Capability

**错误方向：**
```
Capability(memory.search)    ← 禁止
```

**正确方向：**
```
Capability
  └── MemoryProvider
```

**理由：** Memory 是 Provider，不是 Capability。Capability 是原子操作（read/write/execute），Memory 是存储后端。混合会导致 Capability 职责膨胀。

---

### 禁止 3：AgentIdentityRegistry 不负责执行

**错误方向：**
```
Agent.execute()    ← 禁止
```

**正确方向：**
```
Identity → Decision → Capability → Engine
```

**理由：** Registry 负责"谁"，Decision 负责"做什么"，Runtime 负责"怎么做"。三个职责不可合并。

---

### 禁止 4：PackageRegistry 不保存运行状态

**错误方向：**
```
Package.save_state()    ← 禁止
```

**正确方向：**
```
Package   = what it is
Runtime   = what is happening
```

**理由：** Package 是静态描述（manifest），Runtime 是动态执行（context）。二者不可混淆。Package 描述 Agent 是什么，Runtime 负责当前在发生什么。
